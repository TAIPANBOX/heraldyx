# heraldyx v0.10.0

The checkpoint gate can take its producers' keys from the statements keyryx custody publishes, so a producer that renews its key no longer needs a new pinned file. The file transport now refuses the same header breaks the mail path refuses. vouchryx's delegation events and keyryx custody's key events have their own sentences. The gate stays off unless you switch it on, and no existing setting changes its meaning.

Tag: `v0.10.0`. The image is `ghcr.io/taipanbox/heraldyx:v0.10.0`. There is no moving tag (no `latest`, no `main`).

## Changed since v0.9.1

- #144, the checkpoint gate takes each checkpoint's key from the key statement keyryx custody publishes. This is a new mode, selected by `HERALDYX_CHECKPOINT_STATEMENTS` in place of `HERALDYX_CHECKPOINT_KEYS`. The statements are read from a directory this process mounts read only, and the pinned root is the one in `HERALDYX_CHECKPOINT_ROOT_PIN`. Reading the bus never waits on the directory. The pinned-key mode is unchanged.
- #142, sentences for vouchryx's `delegation_issued`, `delegation_denied` and `delegation_revoked` events, which had fallen to the generic sentence. Keyryx custody's `key_rotated` and `key_revoked` are read from `keyryx-custody.ndjson`, the file custody writes. No key joined the generic allowlist, and no value from an error detail or a free-text reason is printed.
- #141, the file transport (`HERALDYX_MAIL_FILE`) runs the same header check as the mail path. A `To:` or `Subject:` value that holds a control character other than a tab, or a Unicode line or paragraph separator, is now refused.
- #143, a test that runs the checkpoint gate against a real checkpoint writer from agent-stack-go, accepting the stream as written and refusing a one-byte rewrite and a truncation.
- #140, the binding gate for feature files checks where each binding sits. This changes no behaviour of the notifier.
- #138, agent-stack-go moves to v2.0.3, the rebuild on Go 1.27.4.

## Upgrade

Pull `ghcr.io/taipanbox/heraldyx:v0.10.0` and restart. Nothing needs to change for a box that does not use the checkpoint gate.

To use the gate with keyryx custody, set all of the following, and do not set `HERALDYX_CHECKPOINT_KEYS` alongside them:

- `HERALDYX_CHECKPOINT_GATE=on`
- `HERALDYX_CHECKPOINTS`, the directory of `<stream>.ckpt.ndjson` files
- `HERALDYX_CHECKPOINT_STATEMENTS`, the directory custody publishes into (`KEYRYX_STATEMENTS_DIR`), mounted read only
- `HERALDYX_CHECKPOINT_ROOT_PIN`, the kids from custody's `delegation-root.jwks.json`: at least one ES384 and one ML-DSA-65
- `HERALDYX_CHECKPOINT_STREAM_KEYS`, `stream|key-name` for each stream the gate should cover

The gate refuses to start when a required setting is missing. The statements directory must be writable by nobody but its owner and must not be owned by the uid heraldyx runs as. The gate is off by default.

To receive keyryx custody's key events, name `keyryx-custody.ndjson` in `HERALDYX_EVENTS` beside the witness's file.

To roll back, run v0.9.1 again.
