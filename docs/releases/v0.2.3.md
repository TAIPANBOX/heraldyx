# heraldyx 0.2.3

One sentence and the release mechanics' first run.

## What changed

- **A provider that answered and refused gets its own sentence** (#66).
  tokenfuse 1.0.1 raises `dependency_failed` at a new stage, `response`, for
  a reachable provider that refused the call (a 429, a 5xx, a retired model
  id answered 404 or 400; tokenfuse#260). Every stage but `stream` took the
  buffered wording here, "could not be reached ... nothing was charged, and
  the money reserved was released in full", which is false twice for a
  refusal: the provider answered, and a refusal that reported what it
  generated is charged for that. The mail now says the provider answered and
  refused, that the run was charged only what the provider reported
  generating (usually nothing), and what a repeating refusal usually is (a
  rate limit, a retired model id, the provider down; the status is in the
  event's detail). An unknown stage still takes the buffered wording.
- **`release.yml`**: `dist/` is created before the SBOMs (the trap wardryx's
  first tag hit, wardryx#56), and a `workflow_dispatch` takes an existing
  `v*` tag to (re)build the release page without moving the tag; the image
  job runs on the tag push only. This tag is the first through the signed
  mechanics the README describes: image signed keyless and attested, SPDX and
  CycloneDX SBOMs and the provenance bundle on this page.

## Not in this release, said plainly

- The sentence was proven by its test against the event's data, not by a
  mail from a 1.0.1 gateway; the launchers pin this release next, and the
  first refusal on a box is where the mail is first read.
