# heraldyx 0.2.5

Say what a stalled run and a failed call actually established, and nothing more.

## What changed

- **A run that goes quiet has its own message** (#78): TokenFuse 1.0.3's control
  plane raises `run_stalled` (medium) when a run it had seen calling stops. The
  mail names the agent and the run, when the last call was and how long the run
  has been silent, and says plainly that the control plane cannot tell a failed
  node from a long generation or a run that ended without reporting it. The two
  timing fields are rendered only as validated non-negative whole numbers of
  milliseconds; anything else is dropped, never shown.
- **A failed provider call no longer promises a refund** (#79): the mail for a
  `send` failure says the event does not establish whether the provider
  accepted the request, and that an uncertain outcome may keep its reserved
  exposure until it is reconciled; a body that broke after a successful status
  is described as charged at the reported usage or, without it, at the reserved
  estimate.
- **Shared contract dependency** (#77): agent-stack-go v1.0.2; the event,
  passport and chain packages this notifier imports are unchanged between
  v1.0.1 and v1.0.2.

## Evidence and limit

179 test functions; `features/run-stalled.feature` and
`features/failed-call-cost.feature` bind every scenario to a named test; the
mutation cases in `scripts/gates-have-teeth.sh` cover both new renderings.
The wording was read against TokenFuse's settle guard and its `run_stalled`
detector. No SMTP delivery of either message has been measured; the renderings
were checked into files by the tests.
