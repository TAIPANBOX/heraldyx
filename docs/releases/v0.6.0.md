# heraldyx 0.6.0

On a shared volume a reader can be shown an old size for minutes, and a writer's
node can hold bytes the server has not yet received. Before this release, heraldyx
read such a file again from its start, which mailed old alerts a second time, and
it counted a line that was still being written as malformed, which lost its events.
Both are fixed here.

## What changed

- **A read position is given up only for a different file (#104).** Each read
  position now carries a digest of its file's first line, saved beside the offset
  in `state.json` as `heads`. A changed first line means a different file, and it
  is read from the start at once. A smaller size is checked against the data: if
  the byte just before the position is present, the size was old and reading
  carries on. If it is absent, the position is held for up to five minutes, and
  then the file is read again from its start. Before, any file smaller than the
  position was read again from the start at once.
- **A line of zero bytes is held, not counted malformed (#104).** Reading stops
  before such a line and looks again on each poll. After five minutes the line is
  skipped and counted, and the log says that events in that span are lost to this
  process. Before, the line was counted malformed at once and its events were lost.
- **Five counters, printed once per poll.** The log shows the growth of the
  positions held, the positions read again from the start, the files that are a
  different file, the zero-byte lines held, and the zero-byte lines skipped.
- **`state.json` gains `heads`** (invariant 25, invariants 5 and 10 extended). A
  state file written before this release has none, and each file's digest is
  learned on its next read. An older binary reads the file and ignores the field.

## Upgrading

- Nothing to configure. No environment variable was added, removed or renamed.
- This is a minor release because an operator can see the change. A file that
  shrinks while its first line stays the same is now held for up to five minutes
  before it is read again, where it used to be read again at once. Log lines
  appear for each of the five counters.

## Evidence and limit

- Statement coverage, measured on 86e7e27 and on this release: `internal/watch`
  81.3% to 96.4%, `internal/state` 73.5% to 95.9%, `cmd/heraldyx` 78.0% to 96.1%.
- 297 test functions, 79 scenarios in `features/`, each bound to a named test.
- `VALIDATION.md` records the defect and the fix side by side: the same script run
  against both binaries, a restart onto a view cut back to the first line, a
  replaced file, and a zero-filled span.

## Not proven

- The five-minute hold and the zero-byte line were exercised with local files and
  the scripted volume, not on a live shared volume in a cluster, in this release.
- The release and image jobs run only on the tag push.
