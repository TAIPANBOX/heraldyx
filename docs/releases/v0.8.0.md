# Heraldyx 0.8.0

## Upgrade first: mail is sent only over an encrypted connection, and some streams need a group

**1. Mail. Set `HERALDYX_SMTP_TLS` for your server before you start 0.8.0.** Before this release heraldyx tried STARTTLS and sent in the clear if the server did not offer it, and a server that stopped answering could hold the process. Now:

- **A server that offers STARTTLS** (typical on port 587 or 25) needs nothing: `starttls` is the default. The server's certificate is verified against the system roots.
- **A server on port 465** (implicit TLS) needs nothing: that port selects `implicit`. Set `HERALDYX_SMTP_TLS=implicit` to be explicit.
- **A server that does not offer STARTTLS is refused.** Heraldyx will not send to a remote host in the clear. Enable STARTTLS on the server, or move to port 465.
- **`HERALDYX_SMTP_TLS=plain` is allowed only for a loopback host** (`127.0.0.0/8`, `::1` or `localhost`), such as a local relay or a test sink. Any other host with `plain` refuses the start.
- **A server with a certificate from a private CA** is not trusted unless that CA is in the system roots of the host running heraldyx.
- **Every connection has a dial deadline of 10 seconds and a session deadline of 60 seconds.** A server that answered slowly before may now time out.

**2. Streams. Heraldyx reads streams that other services write.** Since agent-stack-go v2 (below), a stream file is created with mode `0640`, not `0644`: the owning account and its group can read it, and no other account can. A new stream file is created only in a directory the writing service's account owns, and an existing file is opened as it is. A bus directory shared with services that run under other accounts gets no new stream unless each file is created beforehand by the uid of the service that writes it, so every service heraldyx reads must do that, or own the directory. Heraldyx reads a stream it did not write only if it is the owner or in the file's group. Before you start 0.8.0, check who owns the bus directory and the mode of each stream file in it.

## Changed since 0.7.0

- **SMTP requires TLS and has deadlines (#116).** This is change 1 above. A failed QUIT after the server has accepted the message is no longer reported as a failure, so a retry cannot send the same alert twice.
- **Keyryx and chain_restarted are described, and an opt-in gate refuses unsigned streams (#117).** The notification text describes the keyryx event types and `chain_restarted`. `HERALDYX_CHECKPOINT_GATE=on` reads a stream file only while a signed checkpoint covers it. It is off by default, so nothing changes unless you turn it on.
- **The agent-stack-go pin moves to the v2 module path, v2.0.0 (#118).** The shared wire-type import moves to `github.com/TAIPANBOX/agent-stack-go/v2`. This is change 2 above.
- **The image is signed in the legacy format (#119).** The image sign step adds `--new-bundle-format=false --use-signing-config=false`, with a comment above it, because the cluster admission controller (policy-controller v0.15.1) reads only the legacy `.sig` tag. cosign stays at v3.1.3. Remove both flags when policy-controller reads bundles.
- **Earlier in the range:** the agent-stack-go v1.3.0 pin (#114) and documentation for `HERALDYX_CONTROL` and the v0.7.0 pull line (#112, #113).

No other commit lies between the 0.7.0 tag and this release.

Pull `ghcr.io/taipanbox/heraldyx:v0.8.0` after you have set `HERALDYX_SMTP_TLS` for your server.
