# Heraldyx 0.8.1

## Upgrade first: an entry that names one stream file must be a regular file

**Check every `HERALDYX_EVENTS` entry that ends in `.ndjson` before you start 0.8.1.** Such an entry names one stream file, and heraldyx now reads it only while it is a regular file, checked with `lstat`:

- **A link at that name is not followed.** Before this release a symlink was read as the file it points at. If an entry is a link today, point the entry at the real file instead.
- **A directory at that name is not expanded.** Before this release a directory named `something.ndjson` was read for every `*.ndjson` inside it. Name the directory without the `.ndjson` suffix, or name the files.
- **An entry heraldyx cannot check is not read**, for example one inside a directory the process may not enter. Before this release such a path was handed to the reader, which reported a `stat` error on every poll.
- **The startup line names each such entry once**, with the reason: a link, a directory, not a regular file, or the `lstat` error. An entry that is not there at all is still skipped quietly and looked for on every poll, as before.

A directory entry, such as the default `/var/lib/stack/events`, is read exactly as before.

Why: the launchers name the Keyryx witness's findings file, `keyryx.ndjson`, as its own entry, on a volume the witness writes. A link or a directory planted at that name would have made heraldyx read another stream, or a set of streams, under the stem `keyryx`.

## Changed since 0.8.0

- **A stream file entry is read only while it is a regular file (#123).** This is the change above. Invariant 33 in `CLAUDE.md`.

No other commit lies between the 0.8.0 tag and this release.

Pull `ghcr.io/taipanbox/heraldyx:v0.8.1` after you have checked your `.ndjson` entries.
