# Heraldyx 0.9.0

## Upgrade first: a provider outage is one mail, and its key changes

**Read this before you start 0.9.0 if you acknowledge `dependency_failed` alerts.** For `dependency_failed` events the dedup key is now the dependency that failed and what the gateway did about it, not the run:

- **Before:** `dependency_failed:<run>`. A provider that is down fails every call that reaches it, every call is its own run, and so an hour of outage was one mail per failed call, up to the hourly ceiling, and a summary of the rest.
- **Now:** `dependency_failed:dependency/provider/call-failed`, one mail per dependency and effect per window. The key is read from the event's own `data.dependency` and `data.effect`. The key is what the mail prints on its `Key:` line and what `--ack` is made against, so acknowledging that key holds the whole storm.
- **An acknowledgement made against the old key does not hold the new one.** If you acknowledged `dependency_failed:<run>` for a run, acknowledge the new key instead, for example `--ack dependency_failed:dependency/provider/call-failed --for 4h --by ops`.
- **The effect stays in the key** because the three outcomes want opposite responses. A gateway that fails open lets calls through with no policy on them, and that is not hidden behind an earlier mail about calls that were refused. The dependencies are `provider`, `policy-plane` and `control-plane`; the effects are `call-failed`, `allowed-ungoverned` and `denied-unasked`.
- **Only the type `dependency_failed` and only those words fold.** An event with no `data`, a dependency that is not one of the three, a value that is not text, a path-like or oversized value, or another event type carrying the same field keeps the key of its run, as before. The key of every other event is unchanged.
- **The link in the mail does not move.** It is built from the incident id the money plane files under, the type and the run, exactly as before.
- **The event contract does not change** and no `data` key is added to the render allowlist. The raw field values are controls for the phrasing and are never printed, which is why the key spells them with hyphens.

Nothing else an operator sets or sees changes: no variable, no file and no mail text other than the `Key:` line of a `dependency_failed` mail.

## Changed since 0.8.2

- **A `dependency_failed` dedups on the dependency, so a storm is one mail (#129).** This is the change above. 13 scenarios in `features/a-dependency-storm-is-one-mail.feature`, each bound to a test, and invariant 34 in `CLAUDE.md`. The README describes the rule and the test badge reads 452.
- **The agent-stack-go pin moves to v2.0.2 (#128).** v2.0.2 is the Go 1.27.3 rebuild of v2.0.1 and changes no source file here.
- **Three GitHub Actions move (#127).** `docker/login-action` to v4.7.0 in the release workflow, `ossf/scorecard-action` to v2.5.0 and `github/codeql-action/upload-sarif` to v4.39.1 in the scorecard workflow.

No other commit lies between the 0.8.2 tag and this release.

Pull `ghcr.io/taipanbox/heraldyx:v0.9.0`, acknowledge the new key where you had acknowledged a `dependency_failed` run, and restart.
