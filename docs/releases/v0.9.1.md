# heraldyx v0.9.1

The notifier and its image are built with Go 1.27.4, which fixes GO-2026-6859 in `net/http`. The v0.9.0 image was built with Go 1.27.3. No allowlist key, severity, dedup key or rule changes.

Tag: `v0.9.1`. The image is `ghcr.io/taipanbox/heraldyx:v0.9.1`. There is no moving tag (no `latest`, no `main`).

## Changed since v0.9.0

- #135, `build: Go 1.27.4 for GO-2026-6859`. The `toolchain` line in `go.mod`, the CI `go-version` and the Go version of the `Dockerfile` move to Go 1.27.4.
- #132, the `slo_burn` mail no longer says that nothing automatic follows an exhausted budget. Where Wardryx is started with `WARDRYX_SIGNAL_EVENTS` and its policy has a `hold_if_signal` rule on `slo_burn`, it puts the agent's tool calls to a person while the budget is spent, and the sentences now point to that hold. Only the text of the mail changes.
- #133, the gates no longer end a pipe in a `grep` that exits early (invariant 35).
- #131, documentation: Wardryx reads the `slo_burn` stream, trailryx maps `alert_sent`, and `agent-conform` has three rows.
- #134, the actions in the workflows move to newer pinned commits.

## Upgrade

Pull `ghcr.io/taipanbox/heraldyx:v0.9.1` and restart. No configuration or state changes. To roll back, run v0.9.0 again.
